# Git vs SVN — ответы на вопросы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто легковесный указатель (текстовый файл размером 41 байт с хешем целевого коммита), создание которого происходит мгновенно за $O(1)$ и не требует дублирования данных, так как все коммиты и файлы хранятся в единой базе объектов репозитория. В SVN ветка концептуально представляет собой операцию копирования каталога (`svn copy`) из `trunk` в `branches/<имя_ветки>` на центральном сервере. Хотя на стороне сервера применяется механизм copy-on-write, локальное переключение и работа с ветками (`svn switch`, `checkout`) требуют обмена данными с сервером и обновления файловой структуры, что существенно медленнее и «тяжелее» локальных операций Git.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, в SVN сделать коммит без сетевого подключения к центральному серверу невозможно. Архитектура SVN является централизованной: рабочая копия на компьютере разработчика хранит только текущее состояние файлов, а вся история ревизий и база метаданных находятся на удаленном сервере. Команда `svn commit` обязана связаться с сервером для проверки актуальности рабочей копии и присвоения новой глобальной ревизии. В распределенной системе Git каждый локальный репозиторий содержит полную копию истории (`.git`), поэтому создание коммита — это строго локальная и мгновенная операция, не зависящая от сети.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

1. **Крупные репозитории с большими бинарными файлами:** В геймдеве и мультимедийных проектах, где кодовая база содержит гигабайты 3D-моделей, видео и звуковых ассетов. SVN позволяет выполнять частичный чекаут (sparse checkout) только нужной папки без необходимости скачивать всю историю репозитория (в Git для этого требуется отдельная настройка Git LFS).
2. **Эксклюзивная блокировка файлов (File Locking):** Для неделимых бинарных файлов (текстуры, макеты, скомпилированные ресурсы), где автоматический merge невозможен, механизм `svn lock` позволяет заблокировать файл на время редактирования, предотвращая возникновение конфликтов между сотрудниками.
3. **Гранулярный контроль доступа к директориям:** Возможность задавать права на чтение и запись на уровне отдельных подпапок внутри одного репозитория, что востребовано в регламентированных банковских и корпоративных структурах.
